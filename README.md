# RetinaVision

RetinaVision is a monorepo for an ophthalmic image analysis and clinical review
system. It combines a Vue web application, a Spring Boot business backend, and
a FastAPI/PyTorch inference service with MySQL, Redis, RabbitMQ, and Qdrant.

> AI output is assistive only. Image quality scores and vessel segmentation do
> not constitute a medical diagnosis. A responsible doctor reviews the result
> and signs the formal report; the system never signs a report automatically.

## Architecture

```text
Browser
  | HTTP /api
  v
Vue :5173 ---> Spring Boot :8080/api ---> MySQL
                    |  |  |
                    |  |  +------------> Redis (rate limits, JWT denylist, quota)
                    |  +---------------> Qdrant (RAG vectors)
                    +------------------> RabbitMQ
                                           |
                                           v
                                      Java consumer
                                           |
                                           v
                                  FastAPI/PyTorch :8000
```

The RabbitMQ consumer runs inside the Java backend. Python performs model
loading and inference only; it does not access the business database or accept
browser JWTs.

## Role boundaries

- **Patient (`USER`)** creates a draft examination request, selects a doctor,
  uploads images, submits or withdraws when allowed, tracks progress, and reads
  signed reports. Patients cannot create, retry, or cancel technical AI tasks.
- **Doctor** accesses only assigned patients, decides whether to run vessel
  segmentation after reviewing the quality score, reviews results, and signs
  reports.
- **Administrator** manages accounts and platform governance such as quality
  control, Prompt/RAG evaluation, knowledge documents, and dead letters, but
  cannot read clinical details.
- **Researcher** currently uses the audience-filtered knowledge assistant only.

The role-aware Agent remains read-only. Native clinical Skills execute scoped
queries in Java; medical knowledge questions use restricted tool calling.

### Agent evaluation

Administrators use the Agent evaluation center to validate doctor and patient
Agent behavior against a versioned, anonymous 180-case dataset. A run freezes
the selected model, Skill versions, Router Prompt version, and dataset version,
then measures routing, argument extraction, query assertions, structured
responses, safety, citations, and latency. Evaluation fixtures never query or
modify clinical tables and do not create production chat sessions or Skill
execution logs.

Repository tests use deterministic adapters and do not call an external model.
Only an administrator-triggered evaluation calls the configured Aliyun
OpenAI-compatible service, one case at a time. Passing automatic thresholds is
not enough to activate a candidate: an administrator must also review and
approve the run. Evaluation never activates a Prompt or Skill automatically.

### Patient Agent

Patients can ask natural-language questions such as:

- `我有哪些检查？`
- `我最近一次检查到哪一步了？`
- `哪些图像需要重新上传？`
- `查看我的最新正式报告`

Case lists, progress, and signed-report lookup are native read-only Skills. They
query only the signed-in account's patient profile and return structured cards
without sending case rows to the LLM. Patient medical knowledge uses RAG with
only `PUBLIC` and `PATIENT` documents. A signed-report explanation may use the
LLM, but only after authorization and only with allowlisted signed fields; if
generation fails, the original signed report remains available.

Patient cards never expose quality scores or thresholds, model metadata, task
logs, image or mask paths, drafts, or unsigned doctor opinions. Page actions
are generated by Java and limited to case progress, the signed-report section,
and image upload. The Agent cannot submit, withdraw, delete, create technical
tasks, review, or sign on the patient's behalf.

## Prerequisites

- JDK 17 and Maven 3.9+
- Node.js 20 and npm
- Python 3.11 and a matching CPU/CUDA PyTorch build
- Docker Desktop (or separately managed MySQL, RabbitMQ, Redis, and Qdrant)
- Local model checkpoint at `ai-service/models/model_new.pth`

Do not commit `.env` files, credentials, model weights, uploaded images, masks,
reports, logs, or other runtime data.

## Local startup

All commands below run from the repository root.

### 1. Infrastructure and AI container

Create a local environment file and replace every placeholder with a local
secret. The resulting `docker/.env` is ignored by Git.

```powershell
Copy-Item .\docker\.env.example .\docker\.env
docker compose --env-file .\docker\.env -f .\docker\docker-compose.yml up -d
docker compose --env-file .\docker\.env -f .\docker\docker-compose.yml ps
```

Compose exposes services only on loopback by default: MySQL `3307`, RabbitMQ
`5672` and management `15672`, Redis `6379`, Qdrant `6333`, and AI `8000`.

To run AI outside Docker instead, use a dedicated PowerShell terminal for this
foreground process. `Push-Location`/`Pop-Location` restores the repository root
after the server stops:

```powershell
Push-Location .\ai-service
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m uvicorn retinavision_ai.api:app --app-dir src --host 127.0.0.1 --port 8000
Pop-Location
```

### 2. Java backend

Create the ignored `src/main/resources/application-dev.yaml` from your local
service settings. Keep database, RabbitMQ, JWT, LLM, and embedding secrets in
that ignored file or Windows user environment variables.

```powershell
mvn spring-boot:run
```

The browser API is available at `http://127.0.0.1:8080/api`.

### 3. Vue frontend

```powershell
npm.cmd --prefix .\frontend ci
npm.cmd --prefix .\frontend run dev
```

Open `http://127.0.0.1:5173`. Vite proxies `/api` to the Java backend.


## Runtime data

The backend stores local uploads and generated results under ignored upload
roots. The AI service stores normalized inputs and masks under
`ai-service/storage/`. These artifacts may contain sensitive medical data and
must remain outside source control with an explicit retention policy.
