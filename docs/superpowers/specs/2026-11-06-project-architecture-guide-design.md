# RetinaVision 项目架构指南设计

## 意图

为 RetinaVision 编写一份面向新接手开发者和项目讲解者的系统架构指南。文档首先解释系统如何运行，再说明代码位于哪里，最后给出阅读顺序。重点是 Java 后端结构、模块职责、复杂业务编排和安全边界；Vue、Python 与 Docker 只说明组织方式和协作关系。

## 目标

- 用一份文档串联浏览器、Spring Boot、MySQL、Redis、RabbitMQ、Python 推理服务、Qdrant 与外部 LLM。
- 解释根目录、Java 分层目录及主要功能子目录的职责。
- 为 Controller、Service、Mapper、POJO 等代码提供可检索的职责索引。
- 深入说明 Agent、异步推理、临床审核、报告签发、RAG、评测和权限隔离等复杂链路。
- 给出按学习目标组织的代码阅读路线。

## 非目标

- 不逐行翻译源码。
- 不逐个解释 Getter、Setter、构造器和 MyBatis-Plus 基础 CRUD。
- 不编写包含全部字段的数据库字典。
- 不深入讲解 Vue 页面视觉实现和 Python 模型数学原理。
- 不使用旧计划替代对当前 `master` 代码的核对。

## 采用方案

采用“整体架构与业务链路优先，目录词典和类方法索引随后”的混合结构。

曾考虑的其他方案：

1. 目录优先：文件容易查找，但同一业务流程会被技术分层拆散。
2. 业务优先：容易理解运行过程，但难以作为日常代码索引。
3. 混合结构：先建立系统运行模型，再提供目录和核心类索引。该方案兼顾理解与查找，适合当前项目规模。

## 内容结构

1. 项目定位、角色和能力边界。
2. 整体组件图与请求流向。
3. 根目录词典。
4. Java 后端分层规则和功能包词典。
5. 后端功能模块手册。
6. 核心类与方法索引。
7. 核心业务调用链和时序图。
8. 数据表组、状态机与事务边界。
9. Vue、Python、Docker 的简要结构。
10. 测试体系、架构约束和代码阅读路线。

## 说明粒度

- Controller：说明控制器职责、主要接口、角色要求及委托的 Service，不展开简单方法实现。
- Service 接口：列出业务能力；简单方法用一句话说明用途。
- Service 实现：仅深入复杂编排、状态流转、幂等、安全和事务方法。
- Mapper：基础 CRUD 按规则说明；详细解释对象级权限、自定义筛选、统计与分页 SQL。
- POJO：解释 Entity、DTO、VO、Command、Event 的边界和主要对象，不逐字段抄录。
- 私有方法：只记录承担权限校验、状态机、幂等、路径安全或复杂转换的方法。
- 数据库：按表组和关系说明，不逐列形成数据库字典。

## 表现形式

- 使用 Mermaid 组件图和关键时序图。
- 使用目录树、职责表、方法表和调用链说明。
- 代码路径使用仓库相对路径，便于搜索和长期维护。
- 代码片段与解释分开，只引用能说明边界的短片段。

## 验收标准

- 文档中的目录、类名、方法名和配置文件均能在当前仓库找到。
- 覆盖认证、病例、影像、任务、推理、临床审核、报告、Agent、RAG、治理与运维模块。
- 明确医生、患者和管理员的数据与能力隔离方式。
- 前端、推理服务和 Docker 有完整但不过度深入的组织说明。
- 不包含密码、Token、真实患者信息或本地绝对路径。
