# 患者 Agent 自然语言服务闭环设计

## 1. 背景与目标

RetinaVision 已具备患者病例、图像上传、检查进度、医生审核、正式报告和角色化 Agent 基础能力。医生 Agent 已通过 Skill、Native 查询和受控动作实现自然语言查询，但患者侧仍缺少完整的自然语言服务闭环。

本阶段将现有 `USER` 角色明确作为患者本人，为患者提供一个只读、可解释、可追溯的智能助手。患者可以用自然语言查询自己的病例、检查进度、图像重传提示和已签发报告，并在必要时跳转到对应业务页面完成操作。

成功标准：

- 患者无需理解任务编号、模型状态或技术日志，即可询问本人检查状态。
- 确定性数据查询不依赖大模型总结，模型异常时仍能展示正确结果。
- 报告解释只能基于已签发报告，并明确区分医生原文与 AI 通俗解释。
- 患者 Agent 不能执行写操作、访问其他患者数据或暴露临床技术细节。
- 多轮表达、分页、历史恢复和受控页面跳转形成可用的前端闭环。

## 2. 范围

### 2.1 本阶段包含

- 本人病例列表查询。
- 指定病例检查进度查询。
- 图像质检通俗状态和重传原因查询。
- 本人已签发报告查询与通俗解释。
- 面向患者受众的医学知识检索。
- “继续”“上一页”“查看第二个”“解释这份报告”等多轮上下文。
- 病例、进度、报告和重传页面的受控跳转。
- 患者 Skill 路由评测、权限测试、降级测试和前端验收。

### 2.2 本阶段不包含

- Agent 直接上传或删除图像、提交或撤回检查、改派医生。
- Agent 创建、取消或重试 AI 任务。
- 读取原始 AI 结果、mask、模型指标、技术日志或未签发报告。
- 修改、补写或重新诊断医生报告。
- 诊断、治疗方案或具体处理完成时间预测。
- PDF 文件识别、原始图像分析或任意 URL 跳转。

## 3. 总体架构

患者 Agent 采用 `Skill Router -> Patient Skill Orchestrator -> Native/LLM` 的混合架构，与医生 Agent 的工程模式保持一致，但拥有独立的 Skill、工具集合、字段白名单和安全策略。

请求流程：

1. `PatientAgentSkillRouter` 接收当前患者、会话上下文和用户消息。
2. Router 输出受控 `skillCode`、置信度和参数；上下文命令优先由确定性解析器处理。
3. `PatientAgentSkillOrchestrator` 校验角色、会话归属、参数和对象权限。
4. 确定性查询由 `PatientAgentQueryService` 执行并直接生成结构化数据。
5. 只有报告通俗解释和医学知识问答进入 LLM；其输入严格遵循字段白名单。
6. 服务保存结构化助手消息、分页上下文、受控动作和审计摘要。
7. 前端以结构化数据为准渲染卡片，LLM 文本不得覆盖或篡改查询结果。

患者 Agent 不复用医生临床工具或管理员治理工具。工具按当前 Skill 动态注册，不配置全局默认工具。

## 4. Patient Skills

### 4.1 `MY_CASE_LIST`

用于回答“我有哪些检查”“最近有哪些病例”“哪些图像需要重新上传”等问题。

- 查询范围固定为当前账号绑定的 `patient_profile`。
- 默认按 `medical_case.updated_at DESC, medical_case.id DESC` 排序。
- 每页默认且最多 10 条，不一次性把全部病例发送给模型。
- 支持流程状态、是否需要重传、是否已有正式报告等受控筛选。
- 返回病例号、眼别、流程状态、通俗质检状态、正式报告状态和更新时间。

### 4.2 `MY_CASE_PROGRESS`

用于回答“最近一次检查到哪一步了”“医生处理完了吗”等问题。

进度固定映射为四个患者可理解的阶段：

1. 已上传图像。
2. 图像质量检查。
3. 医生处理。
4. 正式报告。

响应只展示当前阶段、已完成阶段、最近更新时间、下一处理角色和通俗提示。系统不预测具体完成时间。

### 4.3 `MY_SIGNED_REPORT`

用于查询、查看和解释本人已签发报告。

- 只返回已签发版本，草稿和待审核版本不可见。
- 基础查询和报告卡片由 Native 服务生成。
- 通俗解释只使用医生所见、审核结论、处理建议、签发时间等允许字段。
- 不向模型发送 PDF 二进制、文件路径、原图、mask、技术日志或历史草稿。
- 输出必须分别标明“医生报告原文”和“AI 通俗解释”。
- AI 不得改变医生结论、补充新诊断或提供治疗方案。

### 4.4 `PATIENT_KNOWLEDGE_QA`

用于回答患者教育性质的医学知识问题。

- 继续使用现有 Qdrant 检索与引用校验。
- 只检索受众范围为 `PUBLIC` 或 `PATIENT` 的知识文档。
- 无有效命中时不调用 LLM，并明确说明暂无可靠知识依据。
- 回答必须包含可验证引用和固定免责声明。

## 5. 查询服务与对象权限

新增 `PatientAgentQueryService`，通过专用 Mapper SQL 执行患者查询。所有病例和报告 SQL 必须直接包含当前账号对应的 `patient_id` 或 `account_user_id` 条件，禁止先全局查询再在 Java 中过滤。

服务能力包括：

- `listMyCases(criteria, page, pageSize, currentUser)`
- `getMyCaseProgress(caseReference, currentUser)`
- `listMySignedReports(caseReference, page, pageSize, currentUser)`
- `getMySignedReport(reportReference, currentUser)`

对象不存在和越权统一返回“资源不存在”。任何响应不得包含姓名、手机号、身份证、文件绝对路径、原图地址、mask 地址、模型参数、未签发意见或技术日志。

## 6. 图像质检展示规则

患者端只展示通俗状态和重传原因，不展示原始评分、阈值、模型名称或任务日志。

通俗状态固定为：

- `CHECKING`：图像正在检查，请稍候。
- `ACCEPTABLE`：图像已接收，等待医生处理。
- `REUPLOAD_RECOMMENDED`：建议重新上传，并显示经过白名单映射的通俗原因。
- `UNAVAILABLE`：当前无法确认图像质量，请稍后重试或联系负责医生。

重传原因由 Java 根据受控错误码或质量标签映射，例如“图像较模糊”“拍摄区域不完整”“亮度不合适”。不得把模型原始错误或技术异常直接展示给患者。

图像质量检查仍然只作为辅助参考；医生可以查看完整评分并决定是否继续进行血管分割。

## 7. 会话上下文

患者会话上下文保存：

- 当前 Skill 和筛选条件。
- 当前页码、总数和最多 10 个当前页内部引用。
- 当前选中的病例和已签发报告引用。
- 上下文更新时间和过期时间。

“继续”“上一页”“查看第二个”“解释这份报告”等命令由确定性解析器优先处理。序号只能引用当前页；引用越界、过期、状态变化或权限失效时，要求患者重新查询。

上下文不保存原图、报告全文、医生草稿、模型结果或患者真实身份信息。新主题替换不相关的旧筛选，避免错误继承上下文。

## 8. 响应和受控动作

沿用 `POST /agent/chat`，保留现有文本、工具摘要、引用和免责声明字段，并通过结构化内容返回：

- `CASE_LIST`：病例列表。
- `CASE_PROGRESS`：四阶段检查进度。
- `SIGNED_REPORT`：已签发报告卡片和可选通俗解释。
- `KNOWLEDGE_ANSWER`：知识回答与引用。

允许的患者动作：

- `NEXT_PAGE`
- `PREVIOUS_PAGE`
- `VIEW_CASE_PROGRESS`
- `VIEW_SIGNED_REPORT`
- `GO_TO_IMAGE_UPLOAD`

目标路径由 Java 根据动作枚举和已鉴权对象生成。模型不能提供任意 URL，也不能生成直接写操作动作。“重新上传图像”和“撤回检查”等请求只能返回业务页面入口及操作说明，最终操作由患者在页面中确认。

## 9. 前端体验

患者智能助手提供以下快捷问题：

- 我的检查有哪些？
- 最近一次检查到哪一步了？
- 哪些图像需要重新上传？
- 查看我的最新正式报告。

结构化展示包括：

- 病例列表卡：病例号、眼别、流程状态、更新时间。
- 进度卡：四阶段状态、最近更新时间和下一处理角色。
- 重传提示卡：通俗原因和“前往图像管理”动作。
- 报告卡：签发时间、医生结论摘要、“查看报告”和“通俗解释”动作。

列表每页最多 10 条，提供上一页和下一页。窄屏使用单列布局。重新打开历史会话时恢复卡片、分页、引用和受控动作，不仅恢复纯文本。

## 10. LLM 输入与降级

允许送入 LLM 的患者数据仅包括：

- 匿名患者编号。
- 病例号、眼别、流程状态和更新时间。
- 已签发报告的允许结构化字段。
- 已通过受众过滤和引用验证的知识片段。

发生异常时：

- 查询失败：不调用 LLM，返回可重试错误。
- 查询成功但 LLM 超时或协议异常：保留结构化数据，解释区域显示暂不可用。
- 模型输出与结构化数据冲突：以结构化数据为准，并使用固定模板重建摘要。
- 报告解释触发安全规则：保留医生原文，拒绝不安全解释。
- RAG 无有效引用：不生成无依据回答。

## 11. 审计

复用现有 Agent 会话、消息、Skill 执行和工具调用审计能力。审计记录 Skill、版本、成功状态、耗时、错误类型、脱敏参数摘要和受控动作，不记录 JWT、API Key、完整 Prompt、PDF 内容、患者真实身份、文件路径或大段报告原文。

患者只能查看自己的会话。医生和管理员不能通过患者 Agent 会话接口读取患者报告内容。

## 12. 测试与评测

### 12.1 路由与上下文

- 覆盖病例列表、进度、重传、报告、报告解释和知识问答的自然语言变体。
- 验证 Skill、病例引用、报告引用、页码和筛选参数提取。
- 验证“继续”“上一页”“查看第二个”“解释这份报告”。
- 验证越界、过期和状态变化后的引用安全失效。

### 12.2 权限与字段

- 患者只能查询本人病例和已签发报告。
- 伪造病例号、报告 ID、会话 ID 和当前页引用均不能越权。
- 响应中不存在原始 AI 结果、mask、评分、阈值、技术日志、草稿或文件路径。
- 患者 Agent 无法注册医生或管理员工具，也无法执行写工具。

### 12.3 确定性查询

- 病例按 `updatedAt DESC, id DESC` 排序，每页最多 10 条。
- 四阶段进度和下一处理角色映射正确。
- 图像质量只返回通俗状态和白名单原因。
- 仅返回已签发报告。

### 12.4 LLM 与 RAG

- 报告解释只接收允许字段，并保持医生结论不变。
- 模型超时、协议异常和安全拒绝不影响结构化查询结果。
- 患者知识问答只检索 `PUBLIC` 和 `PATIENT` 文档。
- 无引用时不调用模型，伪造引用被拒绝。

### 12.5 前端与回归

- 病例、进度、重传、报告和知识卡片正常展示。
- 分页、多轮上下文、历史恢复和受控跳转正常。
- API 失败后 loading 复位，既有消息和输入不丢失。
- 桌面端和移动端无文本遮挡或异常大块空白。
- 回归 Java、Vue、Python AI、仓库安全和 GitHub Actions。

## 13. 分批实施顺序

1. 患者查询投影、Mapper、Service 与对象权限测试。
2. Patient Skill Router、Native 编排与会话上下文。
3. 已签发报告解释、知识检索与安全降级。
4. 前端结构化卡片、分页、历史恢复与受控动作。
5. 路由评测、全链路回归、文档和 Pull Request。

每一批应形成独立、可测试、可审查的提交，不把无关重构或新的写操作混入本阶段。
